## Unreleased

- `MediaSessionSurfaces`: the door a host uses when it has no `PlayerHandle` to bind. `activate(sessionId:, title:)`, `updateMetadata`, `deactivate` and `activeSessionId` over the one process-wide driver, so claiming the control bar for a named cell no longer means first getting hold of the driver — and a call made while the surfaces are switched off comes back refused with `MediaSessionRefusal.notEnabled` instead of being a `null` the caller has to think to check. `driver` is there for the calls the door does not carry (`setActive(handle)`, the handler itself), and it is the same single driver the kernel uses: two of them would fight over one notification.
- The surface says what the transport is doing. `MediaSessionState` carries a `MediaSurfacePhase` (`idle`/`loading`/`buffering`/`ready`/`completed`) and `publishState` forwards it to the platform, where it used to publish `AudioProcessingState.ready` for everything: a stream that stalled mid-play looked "available, just not playing", a stopped one looked ready, and the control bar is exactly where a viewer decides whether to keep waiting. The driver derives the phase from the handle's own transport state, and a phase change is never held back by the one-second position window — the thing the viewer is waiting for is the one transition that must arrive now.
- The driver implements `MediaBackgroundSession`, and the media surface has one named owner. `activate` takes it (and reports who lost it), `updateMetadata` and `deactivate` are ignored unless the session asking is the one holding it, and `activeSessionId` says who that is. Before this, the kernel's active player, the music module's binding and a host's own multiview switch were three writers on one control bar with no way to tell a late callback from a current one — the multiview case is exactly a stopped player publishing after the new one has already taken the surface. `dispose()` now releases the surface (`releaseSurface`) instead of parking it, because a driver that is gone has nothing left to publish and an idle-but-listed media item is a control bar for a session that no longer exists.
- `MediaSessionConfig.androidStopOnRemoveTask` now does what it says. The field was read by nothing, so every host that set it to stop playback when the app is swiped out of Android's recents kept playing anyway. `MediaSessionHandler` gained `stopOnTaskRemoved` and an `onTaskRemoved()` override that stops when asked, and the driver forwards the config's value — the default (`false`, keep playing from the notification) is unchanged, which is what a music app wants; a live room is the case that needs it on.
- The media notification publishes position at most once a second, while anything the viewer acts on (play/pause, speed, duration, the control list) still goes out immediately. Every transport tick used to be a platform notification rebuild, and the player can report many times a second - a lock screen redraws its bar about once a second whatever the app pushes, so the rest was battery and heat for nothing. A seek or a new song is a different timeline, not a step along this one, so a backwards jump publishes at once.
- A failed platform handshake is remembered. `initialize()` used to let `AudioService.init`'s exception out and leave nothing behind, so a host that caught it — which is what this package tells an app to do, so a missing `audio_service` manifest entry cannot stop the app booting — carried on driving a driver that had no surface, and every `activate` answered `notInitialized`: "not yet", when the truth is "not here, ever". The driver now records that the handshake returned nothing and reports `MediaSessionRefusal.surfaceUnavailable`, and `dispose()` reports `disposed` rather than pretending it never started.
- Test seam: `MediaSessionDriver(handler:)` accepts a handler instead of letting `initialize()` build one through `AudioService.init`, which needs a platform.

## 0.1.0

Initial release.

- Puts **any** player from the kernel on the system media surfaces: Android notification, iOS lock screen and control center, Windows SMTC and Linux MPRIS.
- One line to start: `MediaSessionBootstrap.enable()`, after which every player shows up on the notification automatically.
- Video and audio share the same thing — one notification, one lock screen entry, one set of media keys; only the dressing differs (previous / next become ±10 seconds, the channel name changes), declared through `MediaSessionConfig`.
- Audio focus, interruption handling and pause-on-unplug.
- A handler (`MediaSessionHandler`) and driver (`MediaSessionDriver`) built on `audio_service`.
- Dependency direction: `media_core_audio` depends on this package, so the music module no longer bundles the system media surfaces.
